1 · Data model

Everything starts as one event

  • An event is one action, by one person, at one time.
  • It carries IDs, a name, a timestamp and properties.
  • Amplitude adds fields on arrival, then resolves the person.

2 · Warehouse

How those events reach BigQuery

  • Amplitude processes each event, then exports in batches as often as every 5 minutes.
  • It lands in a dataset you own, loaded with your service account.
  • A second table holds every ID merge, so counts can match.

The numbers match the steps below. Scroll sideways on a small screen.

1

Collect

Your apps
  • Web, TV and mobile SDKs, or the HTTP API
  • SDKs batch events before upload
2

Process

Amplitude
  • Drops repeats by insert_id
  • Assigns amplitude_id, merges IDs
  • Adds location and timestamps
3

Batch

Amplitude
  • As often as every 5 minutes
  • Best effort: under heavy load a batch can cover a longer window
  • Optional event filters
4

Load

Your BigQuery project
  • Event table, partitioned by event_time date
  • Merge IDs table
  • Each sync finishes within ten minutes
5

Check

Amplitude, daily
  • Compares recent event counts
  • Backfills any day that doesn't match
  • Every job shows in Amplitude

Set up once, in your GCP project

  1. Turn on the BigQuery Data Transfer Service.
  2. Create a service account with BigQuery User, BigQuery Data Editor, and a custom role with bigquery.transfers.get, bigquery.transfers.update and bigquery.datasets.update.
  3. Upload its JSON key in Amplitude, under Data, Catalog, Destinations.

Choose what to send

  • Events ingested from today forward, merged Amplitude IDs, or both.
  • Need history? Start a manual sync for past dates.
  • Backfills can create duplicates. Query through the deduplicated_ table function Amplitude creates.

Weekly users, with and without the merge table
-- Project, dataset and table names are placeholders. Use the ones in your export.
SELECT
  COUNT(DISTINCT e.amplitude_id) AS without_merge,  -- 2 for our viewer
  COUNT(DISTINCT COALESCE(m.merged_amplitude_id, e.amplitude_id)) AS with_merge  -- 1
FROM `my-project.amplitude.deduplicated_EVENTS_123456`('2026-09-28', '2026-10-04') e
LEFT JOIN `my-project.amplitude.MERGE_IDS_123456` m
  ON e.amplitude_id = m.amplitude_id;

Before you compare with a chart: event_time is UTC, so match your project's time zone first.

3 · Semantic layer and AI Context

  • AI Context adds what Amplitude can't infer.
  • That can include definitions from your warehouse, added by hand or over MCP.

Who reads it

Why it matters: your warehouse knows who paid and what counts as churn. Amplitude knows what people did before and after, and where they dropped off. AI Context lets an agent use both.

Adding meaning from your warehouse

Your warehouse defines subscriptions, revenue and churn. Put those rules in AI Context. They don't sync on their own, so pick how you keep them current.

By hand, in AI ControlsGood for rules that rarely change
  • Edit the org or project markdown, or upload a markdown file
  • Upload reference files, such as a data dictionary
  • Admins only
Over MCP, from your repoGood for keeping pace with model changes
  1. A pull request to your semantic layer merges.
  2. An agent, such as Claude Code in your CI, writes the markdown.
  3. It calls manage_amp_context (set_org_context or set_project_context) as an admin.
  4. Agents use the new text on the next question.
  • Each MCP call replaces that scope's full text
  • 10,000 characters per scope
  • Reference files upload in AI Controls only
  • Need the values too? Import fields like subscription_status with BigQuery Data Import

4 · MCP

Use Amplitude from your own AI tools

  • Claude, Gemini, ChatGPT and Cursor connect to Amplitude MCP over OAuth.
  • Your tool can call Amplitude's tools itself, or hand the question to Global Agent.
  • Each person sees only what their Amplitude role allows.
An analyst asks Claude: "Why did TV app viewers drop last week?"
Call tools directlyYour AI tool plans every step
  1. get_amplitude_contextLoads AI Context text and settings
  2. search · get_amp_taxonomyGuesses which events and properties fit
  3. query_amplitude_dataRuns each query, one at a time
  4. render_amplitude_chartDraws the result
Best forSimple lookups, a chart you already know, a fully defined query. Faster and cheaper, and you see every step.
Ask Global AgentAmplitude's own agent does the work
  1. ask_global_agentSends the full question
  2. Inside AmplitudeUses your rules, official content, past analyses and taxonomy to pick events, run queries and build charts
  3. get_global_agent_responseReturns the answer with chart links
Best for"Why" questions, multi-step investigations, and building charts in a large or messy taxonomy.

Why hand it to Global Agent? Context.

Your tool stays lightClaude gets the answer and links, not every intermediate query result.

  • Follow-ups continue the same Global Agent thread
